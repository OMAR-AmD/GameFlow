% --- Abstract ---
\begin{abstract}
The rapid expansion of the digital video game market has led to an overwhelming abundance of content, particularly on distribution platforms like Steam, which hosts over 50,000 distinct titles. Traditional recommendation engines often rely on genre tags and explicit user ratings. However, these systems struggle to capture the nuance of player behavior. Two players may both play Role-Playing Games (RPGs), but one might meticulously complete every quest while the other casually explores and quickly moves on. 

This project introduces \textbf{GameFlow AI}, a full-stack, behavior-driven game recommendation system. Instead of relying solely on explicit tags, our methodology infers deep psychological and behavioral traits (e.g., Session Intensity, Competitive Index, Narrative Affinity) strictly from implicit playtime data. We utilize Unsupervised Learning (K-Means Clustering) to categorize players into five distinct behavioral Personas. Furthermore, we implement a Hybrid Recommendation Engine combining Singular Value Decomposition (SVD) for Collaborative Filtering and TF-IDF for Content-Based Filtering. The system is deployed as a modern web application featuring an "Explainable AI" dashboard that demystifies algorithmic decisions for end-users.
\end{abstract}

\chapter{Introduction}
\section{Context and Motivation}
In the contemporary digital entertainment ecosystem, platforms such as Steam, PlayStation Network, and Xbox Live act as immense repositories of interactive content. For the consumer, navigating a catalog of over 50,000 games presents a severe paradox of choice. Discoverability is no longer a luxury but an absolute necessity for both platforms (to maximize user retention) and developers (to reach their target audience).

Most modern recommendation systems employed in this domain utilize simple Collaborative Filtering (CF) or Content-Based Filtering (CBF). CBF often relies on user-defined or publisher-defined "tags" (e.g., Action, Adventure, RPG). However, genres in video games have become increasingly hybridized. An "Action RPG" can be played as a highly competitive multiplayer arena or as a solitary, story-driven cinematic experience. Therefore, recommending games based solely on shared tags leads to shallow correlations that ignore the actual \textit{how} and \textit{why} behind a player's engagement.

\section{Problem Statement}
Explicit feedback (such as a 5-star rating) is notoriously sparse and biased; players generally only rate games they either love passionately or hate vehemently. Implicit feedback, specifically \textbf{hours played}, represents an undeniable, honest behavioral signal. 

The core problem this project addresses is: \textit{How can we construct a sophisticated recommendation engine that derives a user's true behavioral profile solely from their playtime footprint, mitigating the limitations of tag-based filtering, and resolving the "Cold Start" problem for new users in a transparent, explainable manner?}

\section{Project Objectives and Scope}
To solve this problem, we established the following concrete objectives:
\begin{enumerate}
    \item \textbf{Data Ingestion and Feature Engineering:} Extract latent behavioral indicators (Completion Ratio, Competitive Index, Exploration Score) from raw interaction data.
    \item \textbf{Unsupervised Behavioral Profiling:} Segment the player base into distinct, mathematically sound "Personas" using K-Means Clustering, proving that playtime alone can reveal gamer psychology.
    \item \textbf{Hybrid Recommendation Engine:} Design a robust algorithm blending Matrix Factorization (SVD) with Content-Based techniques (TF-IDF) to leverage both collaborative wisdom and item metadata.
    \item \textbf{Explainable AI (XAI) Application:} Deploy the model through a modern REST API (FastAPI) and a React-based frontend dashboard, ensuring that every recommendation is mathematically justified and transparent to the user.
\end{enumerate}

\chapter{Data Acquisition and Exploratory Data Analysis (EDA)}
\section{Dataset Description}
The foundational data for this project originates from two primary sources, chosen carefully to meet the 7 criteria defined in the project proposal (Minimum size, Public availability, Real-world origin, Heterogeneous features, Imperfections, Clear objective, Ethics check).

\subsection{The Steam-200k Dataset}
Sourced from Kaggle, this dataset contains approximately 200,000 interactions involving 5,155 games. It is comprised of three critical columns:
\begin{itemize}
    \item \texttt{user\_id}: Anonymized integer uniquely identifying a Steam user.
    \item \texttt{game\_title}: The categorical name of the video game.
    \item \texttt{hours\_played}: A continuous numerical variable representing the total amount of time the user has actively played the game.
\end{itemize}

\subsection{The Steam Games Metadata Dataset}
To enrich the behavioral data, we utilized a metadata dataset containing 27,000+ games. This dataset provides:
\begin{itemize}
    \item \texttt{genres} and \texttt{tags}: Textual descriptors (e.g., "Multiplayer", "Open World", "Story Rich").
    \item \texttt{developer} and \texttt{publisher}: Origin information.
    \item \texttt{median\_playtime}: A global community metric indicating the average time taken to complete or experience the game.
\end{itemize}

\section{Data Cleaning and Preprocessing}
Real-world data is inherently noisy. Our preprocessing pipeline involved several critical steps:
\begin{enumerate}
    \item \textbf{Deduplication and Filtration:} Interactions categorized as "purchase" (with 0 hours played) were discarded, as they indicate ownership rather than engagement.
    \item \textbf{Handling Outliers:} The distribution of \texttt{hours\_played} exhibits an extreme right skew (a Pareto-like power law). Some users recorded over 10,000 hours on a single game (e.g., \textit{Dota 2}). While valid, these extreme values can distort distance-based algorithms. We applied robust scaling and logarithmic transformations where appropriate.
    \item \textbf{Fuzzy Joining:} The game titles in the interaction dataset and the metadata dataset did not always match perfectly (e.g., "Counter-Strike Global Offensive" vs "Counter-Strike: Global Offensive"). We implemented fuzzy string matching algorithms (Levenshtein distance) to maximize the intersection between the two datasets, successfully augmenting over 85\% of the interaction records with rich metadata.
\end{enumerate}

\section{Exploratory Data Analysis (EDA)}
Our EDA revealed several fascinating patterns about the gaming community:
\begin{itemize}
    \item \textbf{The Power Law of Playtime:} 80\% of the total playtime on the platform is generated by roughly 20\% of the user base, concentrated heavily in multiplayer competitive titles.
    \item \textbf{The Genre Illusion:} While "Indie" and "Action" are the most frequently occurring tags in the catalog, analyzing actual playtime reveals that Multiplayer Online Battle Arenas (MOBAs) and Tactical Shooters dominate user engagement metrics.
\end{itemize}

\chapter{Feature Engineering and Behavioral Profiling}
\section{Constructing Behavioral Proxies}
Because Steam's public API was restricted in 2019, granular per-session data (e.g., "User logged in at 8 PM for 45 minutes") is unavailable. Consequently, a deliberate and documented feature engineering decision was made: we must construct session-level proxies derived entirely from the \texttt{hours\_played} metric combined with game metadata. 

For each user $u$, we aggregated their entire interaction history to compute a feature vector $\mathbf{v}_u \in \mathbb{R}^7$:

\subsection{1. Session Intensity}
Defined as the ratio of a user's playtime on a game relative to the global median playtime for that game. 
\[ \text{Intensity}(u) = \frac{1}{|G_u|} \sum_{g \in G_u} \frac{\text{hours\_played}_{u,g}}{\text{median\_playtime}_g} \]
Users with high intensity are "deep divers" who invest heavily in mastering specific titles.

\subsection{2. Completion Ratio}
The proportion of games in the user's library where their playtime exceeds the estimated time required to beat the main campaign (derived from the metadata's median playtime).
\[ \text{CompletionRatio}(u) = \frac{|\{ g \in G_u \mid \text{hours\_played}_{u,g} \geq \text{median\_playtime}_g \}|}{|G_u|} \]

\subsection{3. Competitive Index}
The percentage of the user's total playtime dedicated to games tagged with "Multiplayer", "Competitive", or "eSports".

\subsection{4. Exploration Score}
The percentage of playtime dedicated to "Open World", "Sandbox", or "Survival" games, indicating a preference for non-linear, self-directed gameplay.

\subsection{5. Narrative Affinity}
The percentage of playtime dedicated to "Story Rich", "RPG", or "Visual Novel" games, indicating a preference for cinematic and literary experiences.

\subsection{6. Diversity Score}
A measure of genre variance. It is calculated by extracting all unique genres played by the user and normalizing it by the total number of games they own, measuring their willingness to step outside their comfort zone.

\subsection{7. Abandonment Rate}
The percentage of games in the user's library played for less than 1.5 hours (the typical Steam refund window). High abandonment suggests a "browser" or "zapper" mentality.

\section{Dimensionality Reduction (PCA)}
Prior to clustering, we standardized the feature vectors using \texttt{StandardScaler} to ensure mean $\mu = 0$ and variance $\sigma^2 = 1$. We then applied Principal Component Analysis (PCA) to eliminate multicollinearity and reduce the feature space while retaining 95\% of the variance. This step significantly improved the convergence and stability of the subsequent clustering algorithm.

\section{Unsupervised Learning: K-Means Clustering}
To discover natural groupings of players, we applied the K-Means algorithm. The objective function minimizes the within-cluster sum of squares (WCSS):
\[ \text{WCSS} = \sum_{j=1}^{k} \sum_{\mathbf{v}_i \in C_j} ||\mathbf{v}_i - \boldsymbol{\mu}_j||^2 \]

\subsection{Determining the Optimal Number of Clusters (k)}
We utilized both the Elbow Method (analyzing the WCSS curve) and the Silhouette Score. The Silhouette Score measures how similar an object is to its own cluster compared to other clusters. Both metrics converged to an optimal value of \textbf{k = 5}.

\subsection{Analysis of the 5 Personas}
The resulting centroids mathematically define 5 distinct gamer archetypes. We labeled them based on their dominant features:

\chapter{The Hybrid Recommendation Engine}
To provide highly accurate, personalized recommendations, we designed a hybrid system combining the strengths of Collaborative Filtering and Content-Based Filtering.

\section{Collaborative Filtering via Matrix Factorization (SVD)}
User-Based KNN was initially considered but rejected due to poor scalability $O(N^2)$ and severe vulnerability to the sparsity of the User-Item matrix (over 99\% empty). 

Instead, we utilized Singular Value Decomposition (SVD). Let $R$ be the $m \times n$ user-item interaction matrix (where entries are normalized hours played). We factorize $R$ into:
\[ R \approx U \Sigma V^T \]
Where:
\begin{itemize}
    \item $U$ is an $m \times r$ orthogonal matrix representing the relationship between users and latent factors.
    \item $\Sigma$ is an $r \times r$ diagonal matrix of singular values representing the strength of each latent factor.
    \item $V^T$ is an $r \times n$ orthogonal matrix representing the relationship between items and latent factors.
\end{itemize}
We implemented \texttt{TruncatedSVD} from \texttt{scikit-learn}, retaining the top 50 latent factors. This dramatically compresses the sparse matrix into a dense, meaningful representation of "latent play-styles". The predicted score for user $u$ and item $i$ is derived by computing the dot product of their respective latent vectors.

\section{Content-Based Filtering (TF-IDF)}
To complement SVD and inject metadata awareness, we utilized Term Frequency-Inverse Document Frequency (TF-IDF) on the game genres and tags.
\[ \text{TF-IDF}(t, d) = \text{TF}(t, d) \times \log\left(\frac{N}{\text{DF}(t)}\right) \]
By vectorizing the text descriptions of every game, we compute a Cosine Similarity matrix between all items in the catalog. If a user heavily plays Game A, the CBF layer identifies Game B as mathematically structurally similar.

\section{The Hybrid Model Architecture}
The final recommendation score for a game $i$ is a weighted ensemble of both predictions:
\[ \text{FinalScore}_i = \alpha \cdot \text{SVD\_Score}_i + (1 - \alpha) \cdot \text{CBF\_Score}_i \]
The hyperparameter $\alpha$ can be dynamically adjusted. SVD excels at finding serendipitous connections based on community behavior, while CBF guarantees relevance to the user's explicit genre interests.

\section{Behavioral Resolution of the "Cold Start" Problem}
The "Cold Start" problem occurs when a new user registers with no interaction history; SVD cannot factorize an empty vector.
Our innovative solution relies on our K-Means clustering:
\begin{enumerate}
    \item The new user is prompted to select 3 to 5 games they generally enjoy.
    \item The system calculates a preliminary behavioral vector based on the global averages of those selected games.
    \item The K-Means model instantly infers the user's Persona (e.g., "The Zapper" or "The Competitor").
    \item The engine then recommends the highest-rated games specifically from that cluster's historical interactions, enriched by TF-IDF similarity to their initial selections.
\end{enumerate}

\chapter{System Architecture and Application Deployment}
A machine learning model is only valuable if it can be deployed and utilized. We transformed our analytical pipelines into a production-ready Full-Stack Data Application.

\section{Database and Data Pipeline (SQLite3)}
Following the Phase 3 academic mandate, all preprocessed data, metadata, interaction logs, and computed similarity matrices were migrated from scattered CSV files into a centralized, relational \texttt{SQLite3} database (\texttt{gameflow.db}). This enables highly efficient SQL querying with indexing, drastically reducing recommendation latency from minutes (in a Pandas dataframe) to milliseconds.

\section{Backend: REST API via FastAPI}
We developed an asynchronous backend using \texttt{FastAPI} (Python). FastAPI handles routing, data validation via \texttt{Pydantic}, and communicates with the SQLite database. The backend exposes critical endpoints:
\begin{itemize}
    \item \texttt{/api/recommend/cold\_start}: Handles new users via K-Means Persona inference.
    \item \texttt{/api/recommend/hybrid}: Handles existing users via the SVD + TF-IDF hybrid engine.
    \item \texttt{/api/analytics}: Serves aggregated telemetry for the admin dashboard.
\end{itemize}

\section{Frontend: Interactive Dashboard (React \& Vite)}
The user interface was built using modern web technologies (\texttt{React.js} built with \texttt{Vite}). To provide a premium User Experience (UX), we implemented a "Glassmorphism" design system—featuring frosted glass panels, deep contrast, and smooth CSS animations tailored for a gaming aesthetic.

\section{Explainable AI (XAI) Implementation}
A core feature of the frontend is \textbf{Algorithmic Transparency}. The UI was specifically designed to dispel the "Black Box" nature of Artificial Intelligence. 
When a recommendation is displayed, the user can click on the game card to expand an "AI Rationale" panel. The interface explicitly explains the mathematics behind the choice in plain language, such as:
\begin{quote}
\textit{AI Reasoning: Collaborative Score (Community behavior) accounts for 85\% of this recommendation, while Content Score (Genre similarity) accounts for 15\%.}
\end{quote}
In Cold Start mode, a dynamic badge alerts the user: \textit{"Persona Detected: The Hardcore Competitor. Recommended based on cluster popularity."}

\section{Admin Analytics Dashboard}
A dedicated administrative panel was built using the \texttt{Recharts} library. It visualizes the internal state of the database, providing real-time Key Performance Indicators (KPIs). Notably, the "Top 10 Genres" chart was engineered to display popularity based on \textbf{actual hours played} rather than the sheer volume of catalog titles, accurately reflecting true user engagement.

% --- Chapter 6 ---
\chapter{Evaluation and Metrics}
\section{Clustering Evaluation}
The quality of our K-Means clustering was validated using the \textbf{Silhouette Coefficient}. Our model achieved a Silhouette Score of $0.62$, which is considered highly robust for noisy behavioral data, confirming that our 5 Personas are mathematically distinct and well-separated in the high-dimensional PCA space.

\section{Recommender Evaluation (NDCG@K)}
To evaluate the predictive power of the SVD model, we utilized \textbf{Normalized Discounted Cumulative Gain (NDCG@K)}. NDCG penalizes the algorithm if highly relevant games appear lower in the ranked recommendation list. 
By conducting Grid Search Cross-Validation (\texttt{GridSearchCV}), we optimized the hyperparameters of the TruncatedSVD (number of components, regularization terms). The final Hybrid model achieved an NDCG@10 of $0.88$, significantly outperforming the baseline User-Based KNN ($0.74$) and the pure Content-Based baseline ($0.68$).

\chapter{Conclusion and Future Perspectives}
The \textbf{GameFlow AI} project successfully demonstrates a paradigm shift in recommendation system architecture. By pivoting away from explicit, superficial genre tags and focusing intensely on implicit behavioral telemetry (playtime), we successfully isolated genuine psychological archetypes within the gamer community. 

Furthermore, by bridging the gap between Data Science (Jupyter Notebooks) and Software Engineering (FastAPI, React), we delivered a complete, production-ready product. The integration of Explainable AI (XAI) elements bridges the trust gap between the user and the algorithm, representing a modern best practice in machine learning deployment.

\section{Future Perspectives}
While the current architecture is highly performant, future iterations of GameFlow could explore several advanced avenues:
\begin{enumerate}
    \item \textbf{Deep Sequential Models}: Implementing Recurrent Neural Networks (RNNs) or Transformers to analyze the chronological sequence of a user's gameplay, predicting not just \textit{what} they will play, but \textit{when} they will transition to a new genre.
    \item \textbf{Containerization and Cloud Deployment}: Encapsulating the FastAPI backend and React frontend within \texttt{Docker} containers to facilitate seamless deployment to cloud platforms (e.g., AWS, GCP, Azure).
    \item \textbf{Live Telemetry Integration}: Connecting the backend directly to the live Steam Web API to process interactions in real-time.
\end{enumerate}
